# FLIP v0.8.6 — обмены наборами и встречные предложения

## Изменения

- **До пяти разных вариантов** карточек у каждой стороны, по одному экземпляру каждого варианта. Например, 2 Epic ↔ 1 Legendary. Обе стороны обязаны предоставить хотя бы одну рейтинговую карточку; пустая сторона запрещена.
- Можно выбрать несколько карт в списке, просмотреть, сколько CP теряет и получает каждый участник, и подтвердить предложение.
- Входящее предложение можно **принять, отклонить или отправить встречное**. Создание встречного атомарно закрывает старое предложение со статусом `countered` и создаёт новое, отправленное первоначальному инициатору. Возвращать старое предложение после этого нельзя.
- Время жизни каждого нового/встречного предложения — 72 часа. Карточки не резервируются, поэтому сервер заново проверяет наличие при принятии.
- Только рейтинговые экземпляры; тестовые экземпляры и F не передаются. Рейтинговые экземпляры из админки полностью равноценны обычным.
- CP пересчитываются на сервере после переноса **всего набора одной транзакцией**. Повтор подтверждения не приводит к повторной передаче.
- +15 XP за успешную сделку (не за каждую карту), максимум пять сделок с XP в сутки; повтор одной и той же пары наборов и пользователей не даёт дополнительного XP. +10 XP за впервые открытый вид карточки начисляется по обычным правилам.
- Старые предложения 1:1, созданные на v0.8.5, остаются совместимыми с новым серверным алгоритмом; их можно принимать, отменять и использовать для встречного предложения.

## Исправление iPhone

При фокусе на элементах `input`, `select` и `textarea` в Telegram WebView перестал происходить нежелательный автоматический зум из-за текста менее 16 px. Все поля внутри игрового контейнера имеют вычисляемый `font-size:16px!important`. Pinch-zoom для доступности не отключён. На физическом iPhone эффект нужно подтвердить вручную после открытия свежей версии.

## Технические гарантии

- SQL: `sql/006_flip_v086_bundle_trades.sql`, новые текстовые массивы `offer_cards`/`want_cards` и ссылка на исходное предложение; существующие колонки 1:1 сохранены для старых записей.
- Запросы `/api/social` подписываются Telegram initData; actor ID берётся только из верифицированной подписи. Новые операции `create` с массивами и `counter` не принимают более пяти карт и отвергают пустые/повторные/пересекающиеся наборы.
- Оба игрока блокируются в стабильном порядке при принятии; все операции с инвентарём, CP, журналом, статусом и XP атомарны.
- Только `service_role` может исполнять серверные RPC. Таблицы обменов закрыты от анонимных пользователей и обычных Supabase-клиентов через grants и RLS.
- Идемпотентность запросов защищена UUID, в том числе для встречных предложений и ответов.

## Что пока не входит в версию

- Бесплатные переводы («Подарить») **не реализованы**. Ими нельзя подменять обмен с пустой стороной.
- Обмен более пяти вариантов с одной стороны, передача нескольких копий одного варианта в одной сделке и смешанные сделки с F — пока не поддерживаются.
- Мгновенные push-уведомления в Telegram не добавлялись; входящие обновляются по кнопке и при открытии вкладки.

Для установки миграции **006 и 007** уже применены к Supabase `flip-game` до продакшен-публикации. Исправление 007 защищает от XP-фарма при возврате той же пары наборов в обратном направлении. Тест цикла с двумя встречными сделками подтвердил ровно +15 XP каждому, а не +30. Дополнительные Vercel-переменные не нужны.
