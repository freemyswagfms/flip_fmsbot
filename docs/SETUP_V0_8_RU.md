# FLIP v0.8 — ПОДКЛЮЧАЕМ НАСТОЯЩУЮ БАЗУ

Эта инструкция написана для владельца FLIP. Код уже лежит в проекте — ничего программировать не надо.

## Перед началом

- Нужен доступ к существующим GitHub, Vercel, Telegram-боту.
- Нужен аккаунт Supabase: https://supabase.com/dashboard
- Сделай резервную копию v0.7.2 и НЕ сбрасывай локальное демо.
- **Не публикуй v0.8, пока не закончены шаги 1–4**: без настроенной базы в Telegram будет экран ожидания сервера.
- Если Vercel уже подключён к ChatGPT, это не означает, что ключи и база автоматически настроились; проверяй настройки самого проекта.
- Никому (даже в чат!) не отправляй **Telegram bot token** или **Supabase secret key**.
- Используй тот же Vercel-проект и тот же домен, иначе придётся отдельно менять URL кнопки Mini App у Telegram-бота.

## ШАГ 1 — создать базу Supabase

1. Зайди на https://supabase.com/dashboard и зарегистрируйся/авторизуйся.
2. Нажми `New project`.
3. Выбери организацию (если просят, создайте организацию).
4. Назови проект, например `flip-game`.
5. Придумай **надёжный пароль базы** (сохрани в менеджере паролей — в FLIP-код он не вставляется).
6. Выбери ближайший доступный регион, например европейский.
7. Нажми `Create new project` и дождись готовности.
8. Слева открой `SQL Editor` → `New query`.
9. В распакованном FLIP v0.8 открой файл `sql/001_flip_v08.sql` через VS Code или Блокнот.
10. Скопируй **весь текст** файла в окно SQL Editor и нажми `Run`.
11. Должно появиться `Success` без красных сообщений об ошибках.
12. Для проверки в новом SQL-запросе выполни:

   ```sql
   select count(*) from public.flip_cards;
   ```

   Должно получиться **26**: 25 обычных карточек Carti и 1 временная Hidden.

**Не надо** вручную создавать таблицы — SQL уже всё делает. Пока этот шаг не выполнен, серверные дропы не заработают.

## ШАГ 2 — найти адрес и секрет Supabase

1. В Supabase открой свой проект → `Connect` или `Project Settings`.
2. Скопируй **Project URL**. Он выглядит как `https://abcdefghijkl.supabase.co`.
3. Открой `Project Settings → API Keys`.
4. Найди ключ типа **Secret**: он начинается с `sb_secret_...`. Если его ещё нет — создай новый Secret key.
5. Не выбирай Publishable (`sb_publishable_...`) и не бери устаревший `service_role` JWT.
6. Секрет пока храни только в защищённом менеджере паролей/буфере обмена. **Не вставляй его в JS, HTML, SQL, README, GitHub или сюда в чат.**

## ШАГ 3 — взять токен существующего Telegram-бота

У тебя уже есть бот, через которого открывается FLIP.

1. Возьми его **действующий Telegram Bot Token** из собственного защищённого хранилища / старой серверной конфигурации `.env`.
2. Если токен не сохранился, открой официального `@BotFather` в Telegram, выбери своего бота через `/mybots`, открой настройки API Token. **Не перевыпускай токен без необходимости:** после перевыпуска старый токен перестанет работать, и другие части бота надо будет тоже перенастроить.
3. Сохрани токен у себя. Не отправляй его в чат и не коммить в GitHub.

## ШАГ 4 — добавить 3 переменные в Vercel

1. Открой https://vercel.com/dashboard.
2. Выбери **существующий проект FLIP**, который уже автоматически публикуется через GitHub.
3. Зайди `Settings → Environment Variables`.
4. Создай три переменные (Name / Value):

   | Name | Value |
   |---|---|
   | `SUPABASE_URL` | URL проекта из шага 2 |
   | `SUPABASE_SECRET_KEY` | Secret key `sb_secret_...` из шага 2 |
   | `TELEGRAM_BOT_TOKEN` | действующий токен твоего бота из шага 3 |

5. Для всех трёх выбери `Production`. `Development` и `Preview` пока можно не включать.
6. Нажми `Save`.
7. ВАЖНО: эти переменные появятся только на **новом деплое**. После настройки нужно опубликовать v0.8.

## ШАГ 5 — обновить файлы на компьютере

1. Сделай копию папки `flip_fmsbot` или сохранённый ZIP v0.7.2.
2. Распакуй `FLIP_project_v0_8.zip`.
3. Скопируй **содержимое папки `FLIP`** внутрь локальной папки GitHub-репозитория `flip_fmsbot`.
4. Подтверди замену файлов.
5. НЕ удаляй/не меняй `.git`, `.gitignore`, `.env` (если присутствуют).
6. Проверь, что в корне репозитория теперь появились папки `api` и `sql`, файл `package.json`, а также привычные `index.html` и `src`.
7. Открой GitHub Desktop. Должны быть изменения во многих файлах.
8. Внизу слева напиши сообщение коммита: `FLIP v0.8 - server foundation`.
9. Нажми `Commit to main`, затем `Push origin`.
10. Открой существующий Vercel-проект → `Deployments`. Дождись статуса **Ready** нового деплоя. Если статус Error, смотри `Build Logs`.

## ШАГ 6 — проверить сервер без секретов

Открой в браузере URL существующего FLIP, добавив:

`/api/flip?health=1`

Например: `https://<твой-сайт>.vercel.app/api/flip?health=1`

Ожидаемый ответ:

```json
{"service":"FLIP","version":"0.8.0","configured":true}
```

- Если видишь `configured: false`, проверь имена трёх переменных и выполни новый деплой.
- Если 404 — Vercel не подхватил папку `api`. Проверь корень проекта в настройках Vercel (Root Directory) и что `api/flip.js` находится в этом корне.
- Если 500 — смотри Vercel → Deployment → Functions → Logs.

Этот тест проверяет только наличие настроек, а не реальное соединение с базой или работу Telegram.

## ШАГ 7 — проверить в Telegram

1. Полностью закрой Mini App.
2. Открой чат **с твоим ботом** и запусти Mini App обычной кнопкой, как раньше.
3. На главной появится отметка о серверном режиме. Если видишь «ОЖИДАНИЕ СЕРВЕРА», не открывай дроп — сначала проверь подключение и настройки.
4. Для **нового серверного аккаунта** должно быть `LVL 1`, `0 F` и **3 приветственных дропа**.
5. Открой все три: среди них должна быть минимум одна **Rare / Epic / Legendary / Mythic**.
6. После приветственных дропов обычный бесплатный дроп станет доступен по серверному таймеру (4 часа от создания аккаунта).
7. Проверь вкладку `Коллекция`: выпавшие карточки должны находиться там.
8. Закрой Mini App и зайди снова: карточки, баланс и прогресс должны сохраниться.
9. Повтори вход в тот же Telegram-аккаунт с другого устройства, чтобы проверить синхронизацию.
10. `ТЕСТ РУЛЕТКИ` работает отдельно: он НЕ начисляет карточки.

### Важные особенности v0.8

- Старые демо-карточки, демо-XP и баланс **не переносятся автоматически**. Это защита экономики игры. Локальный прогресс остаётся в браузере.
- Если открыть FLIP по обычной ссылке вне Telegram, это по-прежнему отдельное **локальное демо**. Такой браузер не может получать настоящие серверные карточки.
- В серверном режиме кнопка сброса аккаунта отключена. Даже при ошибке соединения локальные демо-награды не смешиваются с серверными.
- При обрыве связи во время дропа приложение запоминает номер операции; после восстановления связи можно нажать **«ВОССТАНОВИТЬ ДРОП»**. Вторую награду это не создаёт.
- Пак за 200 F работает на сервере, но новый игрок начинает с нуля. На первых порах проверить покупку получится после накопления валюты.
- Ежедневные задания в v0.8 пока упрощены: три автоматические награды (дроп, новая карточка, открытие пака). Полноценные недельные задания, витрина и обмены ещё не реализованы.
- «Особая коллекция GTA» остаётся макетом, никаких реальных платежей нет.
- Hidden пока остаётся временной демонстрационной карточкой с редкостью 0,005% и отдельной рамкой. Её окончательный арт определим позже.
- Серверная система требует живой проверки в твоих аккаунтах Supabase и Vercel: автоматические тесты кода **не заменяют** запуска SQL и деплоя.

## Что делать при ошибках

- **«Нет соединения с игровым сервером»**: открой через бота, убедись в правильном токене и проверь `/api/flip?health=1`.
- **«Ошибка Telegram»**: закрой Mini App, заново открой через бота. Если повторяется, вероятно неверный `TELEGRAM_BOT_TOKEN`.
- **SQL/DATABASE_REQUEST_FAILED**: открой `Vercel → Logs` и проверь, что SQL запустился успешно. Не публикуй секреты из логов.
- **Четыре часа не прошли**: сервер блокирует повторный дроп; тест рулетки при этом остаётся доступным.
- **На iPhone не поменялась версия**: полностью закрыть Mini App, открыть снова, при необходимости очистить кэш Telegram WebView (это может стереть старое локальное демо, но не серверную коллекцию).

## Безопасность

- НЕ загружай `TELEGRAM_BOT_TOKEN` и `SUPABASE_SECRET_KEY` в GitHub или чат.
- Не открывай SQL функцию для `anon`/`authenticated` ролей — скрипт специально закрывает их доступ.
- Перед полноценным публичным запуском проведи отдельный тест на нескольких аккаунтах, проверь SQL, журналы ошибок, лимиты запросов и резервное копирование Supabase.
- Никаких гарантий работы «в продакшне» без проверки на реальных Telegram/Vercel/Supabase аккаунтах не даётся.

## Если хочешь проверить, действительно ли SQL создал данные

Открой Supabase → SQL Editor → New query и выполни:

```sql
select (select count(*) from public.flip_cards) as cards,
       (select count(*) from public.flip_artists) as artists,
       (select count(*) from public.flip_releases) as releases;
```

Ожидается: `cards = 26`, `artists = 1`, `releases = 5`. В том же проекте при первом входе через Telegram появится запись в таблице `flip_players`. Внутри таблицы виден числовой ID — не публикуй его вместе с другими личными данными.

**Проверка безопасности**: в браузере и GitHub не должно быть переменных `SUPABASE_SECRET_KEY` и `TELEGRAM_BOT_TOKEN` с реальными значениями. Они доступны только серверной функции Vercel. SQL и JavaScript содержат исключительно имена переменных.
