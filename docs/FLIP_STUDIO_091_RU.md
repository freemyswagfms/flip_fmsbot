# FLIP STUDIO v0.9.1 — управление командой, опубликованными карточками и фильтрами

## Что изменилось

### 1. Команда / роли
Владелец (Owner) может переключать роль существующих участников между Editor и Admin и включать/выключать их доступ к STUDIO. Роль Owner защищена, её нельзя изменить обычной формой. Действия записываются в журнал. При смене роли или блокировке изменения на серверных запросах применяются сразу: каждый запрос заново проверяет роль в базе.

**Editor:** черновики, артисты, импорт, изображения до публикации.

**Admin:** всё из Editor + публикация наборов и замена изображений карточек, уже выпущенных в игру.

**Owner:** всё из Admin + управление командой.

### 2. Опубликованные обложки
В Artwork Studio появились переключатели **Черновики / Опубликованные**. В опубликованном разделе перечислены **все текущие релизы игрового каталога**, включая пять оригинальных релизов Carti, даже если они не были импортированы в STUDIO.

Admin / Owner выбирают релиз и редкость, загружают или вставляют новую обложку через Ctrl+V. После кадрирования до WebP 1024×1024 обработанный файл идёт сначала в private bucket, затем сервер проверяет ID опубликованной карточки, права, принадлежность файла и формат WebP и помещает новую версию в public bucket. Сервер меняет только URL изображения по ID карточки в новой таблице `flip_artwork_overrides`.

**Не меняются:** artist/release/card ID, редкость, балансы, инвентари, открытия, торговля и дропы. Старые изображения остаются в репозитории (legacy Carti) или в versioned Supabase Storage. Ранее выпущенные WebP не перезаписываются.

**Важно:** первая загрузка новой обложки **сразу публикует** её в каталог (это не черновик). Новую картинку игроки получают при следующем обновлении данных игры / повторном открытии Mini App. Для опубликованной карты можно заменить оформление отдельной редкости независимо от остальных.

### 3. Релизы отдельного артиста
Клик на артиста в разделе «Артисты» открывает только его релизы. При необходимости нажмите «Показать всех артистов». Данные не сортируются и не смешиваются с релизами других артистов; общий поиск и фильтр статуса работают внутри выбранного артиста.

## Безопасность и инфраструктура

- Серверный маршрут `/api/studio?route=manage` принимает `update_member` только от Owner. Нельзя назначать Owner через этот API или редактировать Owner.
- `replace_artwork` разрешён только Owner и Admin; URL публичных файлов клиент не устанавливает напрямую. Новые картинки не переписывают прежние Storage-объекты.
- Таблица `flip_artwork_overrides` имеет RLS и не доступна напрямую `anon`/`authenticated`. Записывается только серверным service-role ключом.
- `flip_public_catalog()` возвращает прежние ID и URL: при наличии server-managed override приоритет у него, иначе у стандартного опубликованного оформления. Если URL нет, клиент игры продолжает использовать встроенные обложки.
- В лог аудита заносятся изменения ролей и опубликованных изображений, включая предыдущий URL для возможного восстановления.

## Проверки

- CI: Node tests + Vite build STUDIO; отдельные тесты ролей, отображения опубликованных Carti, фильтрации артистов и полного серверного пайплайна опубликованной обложки.
- Миграция Supabase прошла. Проверена пробная подмена URL в транзакции с откатом. Все 56 карточек и их ID остались прежними.
- Вход по email, приглашения по коду, публикация новых релизов и игровая админка выдачи карточек/XP/F не изменялись.
- Полноценная загрузка изображения через браузер Owner требует контрольного действия пользователя — автоматические тесты не имеют доступа к его активной сессии.
